Goal: make the local model (Qwen2.5-3B-Instruct, 4-bit, fine-tuned with MLX LoRA on this Mac) better at writing, changing, fixing and testing code, with verified data and measured results. Nothing below is claimed unless a file was read or a test was run.

Rules: Python code blocks must parse; secrets (AWS, GitHub, OpenAI, Slack, Google keys, private keys) drop the record; deduplication is by normalized instruction across all five sources (tested answers win); tasks that match a Coding AI check (palindrome, merge intervals, run length, second largest, clamp, add days, slugify, is_admin, join words) are excluded so the checks measure generalisation. SWE-bench's train split and test split share **0 repositories**, so evaluation cannot leak into training.

Used per training run (capped so coding does not drown the other skills): 400 OpenCodeInstruct, 300 Evol, 300 OSS, 150 CodeAlpaca, 120 SWE-bench = **1,270 rows**.

## Checks and evaluation

* **Gate (must pass to switch the model on):** 10 Coding AI checks (`training-config/skill-packs.json`) that **run the code**: 8 are executed against hidden unit tests (implement, modify, fix a failing test, write tests that pass on correct code and fail on two broken versions), 2 are pattern checks (consistent multi-file rename, code review). Each check is proven to pass a correct answer and fail a wrong one (`test/coding-pack.js`).
* **Held-out coding benchmark:** 40 OpenCodeInstruct tasks that are never trained on, graded by their own unit tests (`scripts/coding-eval.py`, each test in a fresh `python3 -I` process, 10 s limit).

| Model | pass@1 (all tests of a task) | asserts passing |
|---|---|---|
| Base Qwen2.5-3B-Instruct Q4_K_M | 57.5% (23/40) | 70.2% |

Base model on the 10 gate checks (no fine-tuning): 8/10 (it misses test-writing and the review check).

## SWE-bench evaluation — blocked

The official harness builds one Docker image per task and runs the repository's tests inside it. Docker is installed but its daemon is not running, and the images are x86-64 (slow under emulation on Apple Silicon, tens of GB). A 3B model is also expected to solve close to 0% of SWE-bench. Next step if you want a measured number: start Docker Desktop, then run the harness on a small SWE-bench Lite subset (for example 10 tasks) with the predictions the bot writes. Until then no SWE-bench pass rate is claimed.
