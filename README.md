# Tulai

**New here? See [HOW-TO-RUN.md](HOW-TO-RUN.md)** for setup, running, building, testing and training. Memory and the vector database: [VECTOR-MEMORY.md](VECTOR-MEMORY.md). It uses local SQLite with exact cosine search, not Chroma.

Tulai is two programs in one app, built for software engineers who work behind a company AI gateway.

| | **Tulai Desktop** | **Tulai Bot** |
|---|---|---|
| What | The chat app. Uses your company AI (the LiteLLM/Foundry gateway), the agent harness, skills, the embedded browser, GitHub/GitLab/Jira tools. | The always-on helper: the floating robot, "Hey Tulai" voice, the local AI that understands you, reminders, calendars, meeting notes, Slack/Telegram, missions. |
| Process | `Tulai` | `Tulai --bot` |
| If you quit it | The bot keeps running. | Desktop keeps running. |
| AI used | Company AI (gateway) | Embedded local models (whisper + Qwen). Nothing leaves the Mac. |

They are separate operating-system processes that only talk through local calls. Real work (reviewing a merge request, writing a report, going through email, finishing a ticket) is handed from the bot to Desktop, which uses the company AI.

## Requirements
- Apple Silicon Mac (M1 or newer), recent macOS, Node 20+, Homebrew.
- The speech and understanding models (whisper + Qwen) and the llama.cpp/whisper.cpp engines are **never committed** to this repo. The setup step downloads them (sizes and checksums are listed in `models.json`).
- The app is unsigned (ad-hoc). On another Mac: right-click → Open the first time.

## Install (fresh clone)
```bash
git clone <your-repo> && cd <repo>
./setup.sh              # same as: npm run setup
                        #  - brew install llama.cpp whisper-cpp (if missing)
                        #  - downloads the models from models.json (resumable, sha256-verified)
                        #  - npm install
./setup.sh --build      # also builds Tulai.app
```
Llama and whisper are bundled **inside** the built app and start/stop together with Tulai Bot, so the installed app needs no Homebrew.

## The Tulai skills model (trained on every install, before you use the bot)
The repo ships the **training examples and the recipe**, not the trained weights (weights are never committed). Every install builds the same model on its own Mac:

- `npm run setup` installs the trainer and then trains (about 10 minutes on Apple Silicon). Skip it with `npm run setup -- --skip-first-training`; train later with `npm run training:skills`.
- If the training did not run at install time, the bot does it by itself in the background about 90 seconds after it starts, only while the Mac is plugged in and has free memory. One try a day, at most two tries.
- The result is converted to the format the bot runs and must pass the **regression gate** (exact JSON skills, plain questions, the bot's real command understanding, and natural multi-turn chat). Only then does the bot switch to it, keeping the previous model for **Restore previous model** (Settings, training panel). If anything fails, the bot keeps the base model and nothing is lost.
- What ships (all in `training-config/`): `skills-recipe.json` (the exact settings and the pinned base model), `rehearsal.json`, `nlu-examples.json`, `chat-rehearsal.json` (replayed answers that keep it natural), `nlu-gate-cases.json` (held out, never trained on). The skill examples themselves are generated by `scripts/skill-data.py`, with every answer computed by code. No personal data is included, and `npm test` checks that.
- Status: the Health report has a "Skill training" row, and the training panel shows progress, or the exact reason a candidate was not activated.

## Build, check
```bash
npm run verify          # syntax + "is every file packaged" + all tests (no mic, network or gateway needed)
npm run build           # downloads missing models, compiles the voice helper, bundles engines + models, builds dist/mac-arm64/Tulai.app
npm run smoke           # starts the BUILT app in a private folder and checks it end to end
npm run models:check    # are all models present and valid?
npm run repo:check      # before pushing: fails if a model, build or private file would be committed
cp -R dist/mac-arm64/Tulai.app ~/Desktop/Tulai.app
```

## First run checklist
Open Tulai, then **Settings → Diagnostics → Tulai health**. Fix any red dot:
1. **Microphone** (macOS asks on first launch): allow.
2. **Screen & System Audio Recording**: allow if you want meeting notes to hear the other people while you wear a headset, or Mac control.
3. **Settings → Connection**: your gateway address and key.
4. Optional: **Work tools** (Jira, GitLab), **Calendars** (sign in once to Outlook/Google/Teams), **Chat apps**.

## What you can say ("Hey Tulai, …")
Open apps, websites and projects ("open my mb-mobile project in VS Code"), Chrome with a profile, Teams chat drafts, email drafts (you press Send), time/date/volume/screenshot, reminders ("remind me in 10 minutes about my meeting"), meeting notes ("start meeting notes" / "summarize the meeting"), calendar ("what meetings do I have today"), Jira status, a high-level report by labels, "review the MR of Paolo", "check my email", "write my standup", and robot moves/feelings (dance, dive, cry, giggle, sleep, angry, love, excited …). Works in English, Tagalog and Taglish.

## Where things live
- Data: `~/Library/Application Support/gateway-chat/` (`config.json` is owner-only, chats, `voice.log`, `brain.log`, `errors.log`, `reminders.json`, `calendar-cache.json`).
- `brain.log`: what the bot was asked and how it decided. `voice.log`: what it heard (only the first words of long speech; ordinary conversation is never stored). `errors.log`: unexpected errors (they never crash the bot).
- Meeting notes: `~/Documents/Tulai Meetings`.

## Security model
- The local servers listen on `127.0.0.1` only. Every API call must come from Tulai's own pages or programs: other websites are refused (Host and Origin checks, JSON-only writes). Tested in `npm test`.
- Tokens (gateway, GitHub, Jira, GitLab, bridges) are stored only in `config.json` (owner-only), masked in the UI, and never shown to a model.
- Tulai never types passwords. Calendars and email use a browser session you sign in to yourself.
- Anything that sends or changes something for you (email, Teams message, Jira edit, merge request comment) is a draft you approve.
- Mac control and the agent have an approval step and a protected-apps list (Terminal, password managers, System Settings).

## Troubleshooting
- Nothing answers to "Hey Tulai": Settings → Diagnostics → Tulai health; then `voice.log` (what it heard) and `brain.log`.
- "Tulai Bot is not running": open the Tulai app again (it restarts the bot), or use the menu bar icon.
- Meeting notes only hear you: allow Screen & System Audio Recording, then restart Tulai.
- Slow or odd behaviour on a Mac under memory pressure: the bot warns with smoke over its head; closing Chrome tabs helps. Tulai itself uses about 3 GB for its two models.

## Known limits
- The embedded model is small (3B). Anything needing exact or current facts, long Tagalog answers, or real analysis goes to Tulai Desktop.
- Calendar pages are read from the web page itself and can break if Outlook/Google change their layout. The Teams calendar page is untested.
- Speech recognition of heavily accented or noisy audio is not perfect; Tulai learns how your "Hey Tulai" is heard and logs what it could not match.

### Keep downloaded data out of Git

`npm run setup` downloads model weights to `~/Library/Application Support/gateway-chat/models`, outside the checkout. `models.json` holds the download URLs, byte sizes, and SHA-256 checksums; commit that manifest, not the downloaded weights. Packaging copies runtime assets into ignored `build/models`, `build/bin`, and `dist` folders.

Setup and builds run `npm run repo:check` before downloading or packaging. Run it again before committing. It rejects model weights, private runtime data, and files larger than 5 MiB, including oversized staged blobs whose working copies have since changed. `.gitignore` also excludes generated reports, evaluation artifacts, browser profiles, and vector databases. Git ignores do not remove files already tracked or purge earlier commits. If a generated file is already tracked, review it and use `git rm --cached -- <path>` to untrack it while keeping the local copy. These checks do not install a Git hook or prevent a manual forced commit.

### Reviewed learning examples (no automatic model training)

Tulai keeps proposed corrections under its local data directory in `training/corrections.json`, outside Git. In bot chat:

- `save correction: {"prompt":"Who are you?","expected":"I am Tulai, your partner.","includes":["partner"],"excludes":["trained by you"]}`
- `show learning review`
- `review lesson <id>`
- `approve lesson <id>` or `reject lesson <id>`
- `evaluate lesson <id>`
- `export approved lessons`

Evaluation calls the configured model without tools, history, saved lessons or the target answer. Required/forbidden phrase checks are narrow regression checks, not a factual accuracy score. Export requires human approval and a passing result tied to the example content and current model identity. A failed retest or rejection blocks subsequent exports; previously exported files are immutable snapshots. JSONL exports include a companion provenance manifest. Nothing in this workflow launches fine-tuning, installs an adapter, or replaces Qwen.

## Tulai's background browser

Settings, Accounts: sign in once to Outlook, Google, Teams or any web account. From then on Tulai can read those pages in a hidden window that uses the same signed-in session: "check my Ascendion inbox", "any unread Teams chats", "read https://… in my Metrobank account", or "open Tulai's browser for Metrobank" to see the same session yourself. It only reads (text, links, a picture of the page). It never clicks, sends, or deletes. The Accounts panel has a "Try it" box to test any page.

## What the local AI learns from

Settings, Train your local bot AI, "Your own training":

- **Built-in skills and memory skills.** Exact-answer skills (sent or drafted, counts, percentages, tool calls, reminders) and memory skills (use what is saved about you, say "not saved", newest note wins, never save secrets). Checked by a regression gate on the converted model before it is ever used.
- **Your own examples and checks.** Add them in the panel or drop `.jsonl` files into `<data folder>/training/custom/`.
- **GitHub training pack.** Put a `training-pack/` folder (see the one in this project) in a public GitHub repo; installs download it before training (checksummed, secrets dropped).
- **Free open data.** Dolly 15k (CC BY-SA 3.0), GSM8K (MIT) and OpenAssistant oasst1 (Apache-2.0): human-written, each pinned to an exact commit and file checksum (`training-config/free-data.json`), filtered (English, short, no links or code, no secrets) and capped at a few hundred rows so they season the skills and never replace them. Switch each on or off in the panel; check the license notes before shipping a model outside your company. To add a dataset, add an entry with its pinned URL and sha256 and an adapter in `scripts/free-data.py`.

## Skill packs (one-click fine-tuning)

Settings, Train your local bot AI, "Skill packs": **Jira Mastery**, **Git & Merge Request Mastery**, **Lead Reporting Mastery**, **Meeting Notes Mastery**. Each pack is a bundle of training rows computed by code (never guessed) plus held-out tests it must pass before the model is used. Pressing *Fine-tune* adds the pack to your choice, trains the local model with it (plus the built-in skills, memory skills, free data and your own examples), tests it on the converted model, and switches to it only if every group passes at **90% or better, always** (core skills, commands and chat must be perfect; each pack has 10 tests and may miss at most 1). Otherwise your current model stays and the panel shows which tests failed. Chosen packs are included in every later training.

- **Jira Mastery** uses real Jira knowledge from The Public Jira Dataset (Zenodo [10.5281/zenodo.15719919](https://doi.org/10.5281/zenodo.15719919), CC BY 4.0; only the small definition files are read out of the 5.8 GB archive, each checked against the zip's CRC32; the 5.5 GB database dump is never downloaded) and, if you press Download, real sprint rows from [RandulaKoralage/AgileScrumSprintVelocityDataSet](https://github.com/RandulaKoralage/AgileScrumSprintVelocityDataSet). That repository declares **no license**, so the data is only downloaded on request, used on your Mac and never copied into the app; ask the author before publishing a model trained on it.
- **Updates with releases.** Packs ship inside the app. `scripts/publish-update.js` runs `scripts/pack-versions.js`, which gives a pack the new release version only when the pack's own content (catalog entry, generator code, knowledge file) changed. An installed app compares that with what the model was trained with: the panel shows "update available" and, if allowed (default), Tulai fine-tunes the pack again by itself when the Mac is plugged in and idle, switching only if every check passes.
- **Adding a pack:** add an entry (with `generators`, `checks`, `sources`) to `training-config/skill-packs.json` and the generator functions to `scripts/pack-skills.py`; `npm test` checks that answers recompute and that no check question leaks into training.
- **Regenerating the Jira knowledge:** `python3 scripts/build-jira-knowledge.py`.

## Tulai Desktop models

Settings, "Use Sonnet 5.5 and Opus 5.5 if my gateway has them" asks your company gateway which models it serves and fills in only the 5.5 models it really lists. Tulai Desktop cannot give a model abilities the gateway does not provide: Sonnet 5.5 and Opus 5.5 capability comes from the gateway serving those models.

## First-run setup

After the AI models are downloaded, the setup window offers **Fine-tune now** (tick the skill packs you want) or **Skip for now** (you can fine-tune any time in Settings, Train your local bot AI, Skill packs). It is shown once, and never on a Mac that already runs a trained model.

## The quality bar

A newly trained model is switched on only if it scores 90% or better in every group of the regression gate: core skills 6 of 6, commands 12 of 12, chat 8 of 8, extra and plain questions at most 1 miss of 12, conversation at most 1 miss of 12, memory at most 1 miss of 10, each skill pack at most 1 miss of 10, your own checks at most 10% misses. The base model's own misses never lower the bar.

## Proving a fine-tune works: independent acceptance tests

`npm run test:acceptance` (the local model alone) and `npm run test:acceptance:app` (the whole bot, rules first) ask the **real running Tulai Bot** 100+ questions, one fresh conversation each, and grade the answers. The cases live in `test/acceptance/packs.js`: written by hand, with their own reference calculations in JavaScript, different values and wording than the training templates (which are generated in Python). Two safeguards keep the result honest:

- `test/pack-crosscheck.js` recomputes thousands of the training answers in JavaScript, from the prompt text alone, and fails if the Python answers disagree; it also fails if any acceptance prompt equals a training or gate prompt, or if a check accepts an empty or non-answer.
- The activation gate itself (90% or better in every group, see above) uses separate held-out checks per pack.

Run the acceptance before you ship: a pack is only trusted when it passes there (90% or better per pack). A baseline run before fine-tuning is saved as `training/acceptance-baseline.json` in the data folder for comparison.
