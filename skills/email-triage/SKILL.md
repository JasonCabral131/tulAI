# Email triage

Use the `browser` tool (the embedded Browser tab keeps the user's sign-in). Ask once which mail they use if you do not know (Outlook on the web, Gmail, other) and open it: Outlook https://outlook.office.com/mail , Gmail https://mail.google.com .

If the page asks the user to sign in, STOP: tell them to sign in themselves in the Browser tab and ask again. Never type or request passwords or codes.

1. Read the inbox, newest first, the unread or last 24 hours. Take the sender, subject and the first lines; open a message only when needed.
2. Sort into **Urgent today** (deadlines, boss or client, incidents, approvals waiting on the user), **Needs a reply**, **FYI / can wait**, **Noise** (newsletters, automated). Mention meeting invites with their time.
3. Report the headline first (for example "14 unread: 2 urgent, 5 need a reply") then the urgent ones with sender, subject, and what is being asked.
4. For each "needs a reply", offer a short draft reply in the user's tone. Do not send, delete, archive or mark anything. If the user wants a draft opened in their mail app, open a compose window only after they say so.
